# Orin Python codegen

Stdlib-only generator that turns a **ready** password-reset Orin model into a
standalone Python module (`password_reset_generated.py`). Output is
deterministic; the token lifetime is derived from the model's
`reset-token-expiry` rule.

```text
python -m implementations.python.codegen.generate <model.json> <outdir>
```

Run from the repository root. The model must have compilation `eligible`:
`tests/conformance/password-reset.model.json` still lists the consequential
`rate-limit` uncertainty as unresolved, so it is refused (exit 1, message on
stderr) until a human resolves that decision (e.g. via `orin_agent_core.py`).

Tests: `python -m unittest implementations.python.codegen.test_codegen`
(generates from a rate-limit-resolved copy and replays
`password-reset.cases.json` against the generated module).

The generated password-reset module enforces the accepted
`reset-request-rate-limit` rule (count, window and per-origin scope are parsed
from its claims; `request_reset(..., origin=)`). Models with module
`finance.expense-approval/module` generate `expense_approval_generated.py`
(submit/approve/reject, limit, no-self-decision, final decisions, rejection
reason). Both refuse models that are not ready.

## Model-driven generation

Any other ready model with workflow `transitions` is generated by
`model_driven.py` into `<module-name>_generated.py` plus
`<module-name>_generated.report.json`. A small IR (states, relations,
transitions, guards) is derived from workflow transitions, rule
`requires`/`claims`, and example `expects`; the output is a generic
`Runtime` (`add_entity`, `relate`, `run(workflow, actor, subject)`). Derived
guards: entity-exists, actor-related (membership), assignee-matches,
terminal-state; "do not transition back" claims are verified against the
transitions. Every claim that is not derivable becomes a `NotImplementedRule`
hook, listed in `UNIMPLEMENTED_RULES` and the report; workflow-attached hooks
raise when reached unless supplied via `Runtime(hooks=...)`.
Still hand-written: the password-reset and expense-approval templates, and
claim patterns beyond those above (e.g. relationship-constraints).
Tests: `python -m unittest implementations.python.codegen.test_model_driven`.

## Claim-driven generation (prose rules, no transitions)

Ready models whose workflows have no `transitions` (e.g.
`tests/conformance/library-lending.decided.json`) are generated by
`prose_driven.py`. Recognised claim shapes become generic named constraints:
deadline (`N units after ...`), capped accrual, threshold block, once-only,
blocked-while, exclusive holder, FIFO queue offer/pass-on. Values the model
names but does not fix (rate, limit, cap) are required `Runtime(params=...)`
and listed as `requiredParameters` in the report, as are unresolved
`openQuestions`. Unmatched claims are `NotImplementedRule` hooks.

The input may also be an `.orin` source; apply decisions through
`orin_agent_core` with repeatable `--decide UNCERTAINTY=OPTION`:

```text
python -m implementations.python.codegen.generate examples/library-lending.orin out \
  --decide reservation-hold-expiry=expire-after-3-days --decide renewal-with-reservation=refuse-renewal
```

Test: `python -m unittest implementations.python.codegen.test_library_lending`.
